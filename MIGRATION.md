# Перенос Veirune на новый VPS

После однократного обновления до desktop 0.4.31 / Android 0.1.12 пользователи
получают адрес из подписанного `https://fastcloud.comf.workers.dev/service.json`.
Сайт не проксирует музыку и не получает OAuth. Клиенты проверяют P-256 подпись
закреплённым публичным ключом, сохраняют последнее объявление и не принимают
старый номер объявления. Недоступность сайта не мешает работать с последним
проверенным VPS. Обычная смена адреса обнаруживается примерно за минуту;
плеер заново открывает поток с текущей позиции. Обрыв во время самого переноса
возможен: это восстановление сервиса, а не перенос уже открытого TCP-потока.
Ранее выпущенные клиенты этого протокола не знают — им нужно обычное обновление,
а не удаление и повторная установка. iOS в эту проверку не входит.

## Что сохраняется

- База `/data/approvals.sqlite3`: пользователи, доступы, роли, профильные настройки,
  дизлайки, статистика, чаты и прочие таблицы. Восстановление сверяет всё содержимое
  и схему, а не только число пользователей.
- Прежний `.env`: тот же SoundCloud Client ID, Secret и redirect URI, администратор
  и ключ уведомлений релизов. Меняется только `FASTCLOUD_PUBLIC_IP`.
- Клиентские токены остаются на устройствах. При смене проверенного адреса они
  не удаляются. Новый SoundCloud API application потребует нового входа — поэтому
  восстановление проверяет именно прежнее приложение.
- Исходники: переносится локальный Git bundle `main`; доступ нового VPS к
  приватному GitHub не нужен. Рабочее дерево перед упаковкой должно быть закоммичено.
- Музыкальный кеш и временные медиа-ссылки не обязательны для восстановления:
  они создаются заново. TLS-сертификат выпускается для нового IP.

Копии на D: шифруются DPAPI текущего пользователя Windows. Для расшифровки нужен
этот Windows-профиль. Ключ подписания адресов лежит отдельно в
`D:\VeiruneBackups\service-endpoint-signing.dpapi`; не удалять и не публиковать его.
В Git находятся только публичные ключи и подписанный публичный адрес.

## Проверка копии без воздействия на сервер

```powershell
cd D:\projects\fastcloud-backend
powershell -NoProfile -ExecutionPolicy Bypass -File tools\verify-pc-backup.ps1
```

Последняя реальная копия была расшифрована и восстановлена в отдельную временную
базу; все таблицы и приватная конфигурация прошли проверку. Планировщик: Ready,
последний результат 0. При выключенном ПК или выходе из Windows внешних копий
не будет: аварийная потеря данных ограничивается возрастом последней копии на D:,
а не обещанием нулевой потери. Локальные копии VPS не переживают потерю всего VPS.

## Авария: старый VPS недоступен

Нужен новый Ubuntu VPS с публичным IPv4 и открытыми 80/443. В командах заменить
`NEW_IP` на его адрес. Сначала обычный SSH-вход и проверка ключа нового хоста:

```powershell
ssh root@NEW_IP "exit"
cd D:\projects\fastcloud-backend
powershell -NoProfile -ExecutionPolicy Bypass -File tools\migrate-server.ps1 -Server root@NEW_IP
```

Скрипт берёт последнюю копию с D:, проверяет и восстанавливает базу и `.env`,
устанавливает Docker при необходимости, запускает сервис и IP-TLS прокси,
проверяет HTTPS, здоровье и совпадение API-приложения. Существующее развёртывание
никогда не перезаписывается. При ошибке публичный адрес не меняется.

Только после успешного восстановления публикуется подготовленный адрес сайта:

```powershell
cd D:\projects\fastcloud-website
git add public/service.json public/backend-origin.js public/_headers
git commit -m "ops: move Veirune backend"
git push origin main
```

Дождаться настроенной публикации Cloudflare. Файл должен открываться как JSON,
а не HTML. Подготовка обновляет и адрес публичного статуса, и его CSP.
Номер объявления всегда увеличивается — для возврата на старый VPS нужно
подготовить новое объявление, а не публиковать старый файл.

Перенастроить сборки и уведомления:

```powershell
cd D:\projects\fastcloud-backend
powershell -NoProfile -ExecutionPolicy Bypass -File tools\set-github-server.ps1 -Server root@NEW_IP
```

Обновлённые скрытые копии также читают подписанный адрес: вручную менять задачу
после переноса не нужно. Ключ нового SSH-хоста уже проверен первым шагом.
Если инструменты копирования установлены на другом ПК, обновить их там обычным
`install-pc-backups.ps1 -Server root@NEW_IP -Destination D:\VeiruneBackups` из
PowerShell администратора. Пользовательские приложения не требуют этих команд.

## Плановый перенос без потери записей во время копирования

Перед снимком остановить запись на старом VPS. Эти команды выполнять только
при фактическом переносе, после подготовки нового VPS:

```powershell
ssh root@OLD_IP 'cd /root/fastcloud-backend && docker compose -f compose.ip.yaml stop fastcloud'
cd D:\projects\fastcloud-backend
powershell -NoProfile -ExecutionPolicy Bypass -File tools\backup-to-pc.ps1 -Server root@OLD_IP -Offline
```

Дальше выполнить аварийную процедуру с этой свежей копией. Пока новый сервер не
проверен и адрес не опубликован, старую базу не удалять. Не запускать одновременно
два записываемых экземпляра одной базы: это создаст расходящиеся чаты/настройки.
Если перенос отменён до публикации, старый контейнер можно вернуть командой
`docker compose -f compose.ip.yaml up -d fastcloud`; подготовленное объявление
нового адреса тогда не публиковать, новый снимок создать перед следующей попыткой.

## Проверки и границы

Проверены: реальная зашифрованная копия с ПК, все данные SQLite, приватный конфиг,
подписи/подмена адреса/повтор старого объявления, сохранение custom-серверов,
сборки и тесты клиентов. Новый VPS не предоставлен: Docker/ACME развёртывание
на втором реальном сервере и поведение устройств при настоящем отключении
старого VPS остаются проверкой во время первого переноса. Текущий VPS не
останавливался и публичный адрес в ходе этой работы не менялся.
